# Decisions

1. **Stdlib only.** Zero install on the GB10 (ARM64) removes wheel/arch risk for the core.
2. **Policies are data.** A repair is a reviewable config diff, validated (`validate_config`) before activation, so a model-written proposal is never trusted.
3. **Authority record outside agent context**, immutable mapping (`MappingProxyType`). Gateway has two modes: `live` holds any authority violation; `sandbox` lets the candidate policy decide so each fork's outcome can be observed.
4. **Outcomes are read from backend state** (did the mock backend get called), not from the policy's return value.
5. **Circular metric disclosed.** The authority record is both the guardian and the harm oracle, so "with authority gate" scores 0 by construction. Headline numbers use `policy_only`. A real oracle would be independent, e.g. the mock bank's own ledger rules.
6. **Hard cases kept even though they look bad.** context_bound alone misses provenance-laundered attacks, PII to a trusted recipient and an over-limit amount, and false-denies a legit action whose recipient provenance was untagged. That is the honest case for layering and for runtime-supplied provenance.
7. **Approval binds nonce + actor + exact config digest**, single use, expiring. Agent can request, not approve.
8. **No Telegram HTTP bot.** The brief requires the real OpenClaw channel; a custom bot would misrepresent R03. Only an interface plus a clearly labelled simulated channel exists.
9. **Docker is rootless on this host** (x86_64), started with `DOCKER_IGNORE_BR_NETFILTER_ERROR=1` because `br_netfilter` is missing. Fine for dev; GB10 images must be built or pulled for arm64.
10. **Model replay is sampled proposals judged by every policy, not per-branch inference.** The model never sees the policy, so re-running it per branch would only add noise. The record is labelled `model_sampled_policy_replay`. If a policy-in-the-loop design (agent sees denials and retries) is built, that is a different mode and must be labelled separately.
11. **Parse failures are non-actions, reported, never counted as blocked attacks or completed work.** A model that emits garbage must not inflate either metric.
12. **Agent-facing route is a separate listener** (`adapter_server.py`), not part of the UI server, so an egress preset allowing exactly one path cannot reach the incident runner or any approval route. Approvals are server-side only; `approval_id` from the agent route is refused.
13. **Sandbox forks must see what the live stack sees.** The first eval run showed the sandbox adapter hid `invoice_id`/`currency` from the policy; fixed and disclosed (docs/EVALSUITE.md). General rule: a replay that omits an input the live gate checks can declare a policy safe when it is not.
14. **Review-driven hardening is documented as such**, not as independent validation: the same project authored the fixtures, the code and the fixes.
15. **Evidence gates need host + time + a nonce that exists elsewhere** (event store or `nemoclaw channels list`); a bare proof file never earns PASS.
16. **PAYGUARD / BLACKSITE UI lives at `/payguard/`**, not `/`, so the existing stdlib incident console and its tests stay stable. Built assets ship under `phantomshift/static/payguard/`; source in `payguard-ui/` (2D BLACKSITE as of 2026-10-25; 3D removed).
17. **Dashboard POST routes are read-only or status-only.** Replay POST is idempotent; approval-request returns channel state and explicitly refuses UI-side policy deployment.
18. **Enforcement lives in `ToolFirewall` + `PaymentAdapter`, exposed on the agent listener** (`/api/firewall/before_tool_call` and `/api/adapter/submit`). OpenClaw plugin registers `before_tool_call` plus a single allowlisted payment tool. Finance agents must not receive shell, raw `pay_invoice`, or generic HTTP tools.
19. **Adaptive evaluation is a separately labelled mode** (`adaptive_agent_eval` in `adaptive_eval.py`), distinct from `model_sampled_policy_replay` and `policy_only_replay`.
20. **AUTOPATCH splits fast enforcement from discovery.** Hooks record to SQLite and never call models; research runs in fixture sandboxes only; deploy touches `artifacts/autopatch/policies/` not production OpenClaw policy until GB10 wiring is verified. Discord outbox uses the same dev REST channel with explicit non-OpenClaw footer; interactive approval components remain future work.
21. **BLACKSITE is the 2D product surface** at `/payguard/` (codename BLACKSITE, vertical PAYGUARD). No WebGL/Three in the demo bundle; spatial relationships use React Flow + SVG. Hero metrics pull from `/api/evidence/benchmarks` with explicit HISTORICAL labels — never hardcode operator-reported 20/30 or 0/30 without mode and source.
22. **Authoritative Context Resolution**: Parameter provenance is resolved authoritatively by `authoritative_context.py` using canonical Unicode normalization (NFKC + non-alphanumeric strip) and verified against `Authority` and `GROUND_TRUTH_VENDORS`. Untrusted caller-authored `prov` dictionaries are discarded when authoritative mode is active.
23. **Independent Non-Circular Ground Truth Oracle**: `IndependentGroundTruth` defines harm and legit rules separately from `Authority.rules`, eliminating circularity where the defensive rule defines the scoring metric.
24. **Wilson 95% Confidence Intervals**: Proportions report Wilson score intervals alongside point estimates, preventing false precision on small test splits.
25. **Extended Held-Out Benchmark Suite**: Evaluates 40 distinct cases (20 attacks, 20 legit) across 8 adversarial categories (`unicode_account_spoofing`, `po_amount_manipulation`, `alternate_tool_bypass`, `laundered_provenance_claim`, `approval_tampering_toctou`, `pii_exfiltration_evasion`, `currency_confusion`, `idempotency_conflict`), demonstrating 0/20 attacks succeeded and 20/20 legit tasks completed under the repaired guard.
26. **Agent Skill Packaging (`autopatch-continuous-remediation`)**: Packaged the entire autonomous continuous remediation loop as a standalone, discoverable Agent Skill adhering to the Antigravity Skill Specification. Mirrored across project (`skills/autopatch-continuous-remediation/`), workspace (`.agents/skills/autopatch-continuous-remediation/`), and global config (`~/.gemini/config/skills/autopatch-continuous-remediation/`). Implements stdlib-only scripts (`autopatch_runner.py`, `wire_environment.py`, `rwcr_calculator.py`, `deploy_and_verify.py`), complete with offline environment autodetection, formulaic RWCR prioritization ($3I+2E+3R+N+2Q-2D$), cryptographic digest/nonce approval bindings, and regression-triggered automated rollback.
27. **Discord Outbox Initialization**: `phantomshift autopatch --drain-outbox` initializes `DiscordChannel.from_env()` with robust error handling, ensuring idempotency and preventing crash loops when `.env` is unconfigured or during offline air-gapped runs.
28. **Local Model Serving Fallback (`nemotron-3-nano-4b` on Loopback)**: When physical GB10 / Qwen 3.6 NVFP4 checkpoint is missing (`QWEN_WEIGHTS_MISSING`), serve staged local model fallback `nemotron-3-nano-4b` via `llama-server` on `http://127.0.0.1:8000/v1` through the server guardrails admission launcher (`run_limited_v2.sh cpu --ram 8`). Strictly protect GPU 0 (PID 1151066 active experiment) and enforce zero remote API keys (airgapped).
29. **Phase 1 Machine-Readable Model & Firewall Verifier (`scripts/verify_qwen_route.py`)**: Implements comprehensive host GPU evidence collection, model weight inventory inspection, `/v1/models` probing, plain chat completion timing and token usage, native structured tool-calling verification (`finish_reason: "tool_calls"`, structured `tool_calls` object), prompt injection simulation with live `ToolFirewall` interception (`state: DENIED`, ledger unchanged), and egress airgap auditing, outputting structured evidence to `artifacts/runtime-verification/model_verification.json` and `artifacts/gb10/qwen_route.json`.
30. **AUTOPATCH Outbox Per-Finding Deduplication (`f"finding-{finding_id}"`)**: Updated outbox enqueue deduplication key to `f"finding-{finding_id}"` ensuring that each new research finding successfully queues an embed for Discord delivery, while preserving database idempotency on repeated drains.
31. **Slack Bot Autonomous Control Plane (`SlackChannel`)**: Added full Slack integration as requested, providing a stdlib-only `SlackChannel` (`chat.postMessage`, `reactions.add`, `reactions.get`, `conversations.open`, `conversations.history`) and `slack_views` Block Kit formatters. Tokens stored in `.env` (gitignored, mode 600). Supports operator DM auto-routing (`D0CCV6CKW3A`), reaction-based approvals (`:white_check_mark:` / `:x:`), and outbox draining for AUTOPATCH continuous remediation.
32. **Slack Bolt Socket Mode Agent (`invoice-guard/`)**: Packaged Bolt JS app in `invoice-guard/` operating over WebSocket Socket Mode (`appToken` + `botToken`). Rewrote `agent/agent.js` to dispatch security commands (`scan`, `simulate`, `report`, `status`) strictly against the local, airgapped PHANTOMSHIFT policy engine with zero cloud LLM egress.
